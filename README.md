# سامانه‌ی چندعاملی تولید داستان اختصاصی کودک با AutoGen

تمرین دوم درس LLM Agents. سه عامل مستقل AutoGen — **نویسنده (Author)**، **ویراستار (Editor)** و
**داستان‌گو (Storyteller)** — با گرفتن مشخصات یک کودک و ترجیحاتش، یک داستان فارسیِ اختصاصی، منسجم، ایمن و
مناسب سن او می‌سازند و آن را برای بلندخوانی آماده می‌کنند.

```bash
python main.py --input input.json --output output.json
```

توضیح معماری، نمودار گردش کار، نحوه‌ی مدیریت چرخه‌ی اصلاح، نتایج ارزیابی و تحلیل نمونه‌ی شکست در
[`report.md`](report.md) آمده است.

## نصب

پایتون ۳٫۱۰ یا بالاتر لازم است.

```bash
python3 -m venv .venv
source .venv/bin/activate          # در Windows:  .venv\Scripts\activate
python -m pip install -r requirements.txt
```

وابستگی‌ها فقط `autogen-agentchat` و `autogen-ext[openai]` (نسخه‌ی ۰٫۷٫۵) هستند.

## تنظیم کلید و مدل (AvalAI یا OpenAI)

کلید API هرگز در کد یا مخزن قرار نمی‌گیرد؛ از متغیر محیطی یا فایل `.env` کنار `main.py` خوانده می‌شود.
فایل `.env` در `.gitignore` است؛ نمونه‌ی بدون کلید آن [`.env.example`](.env.example) است.

```bash
cp .env.example .env     # سپس یکی از دو کلید را در .env بنویسید
```

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `AVALAI_API_KEY` | — | کلید AvalAI. اگر تنظیم شده باشد، AvalAI استفاده می‌شود. |
| `AVALAI_BASE_URL` | `https://api.avalai.ir/v1` | آدرس سرویس AvalAI (سازگار با OpenAI) |
| `AVALAI_MODEL` | `gpt-4o-mini` | نام مدل |
| `OPENAI_API_KEY` | — | اگر کلید AvalAI نباشد، مستقیماً از OpenAI استفاده می‌شود |
| `OPENAI_MODEL` | `gpt-4o-mini` | نام مدل برای OpenAI |

یا مستقیم در شل:

```bash
export AVALAI_API_KEY="your_api_key_here"        # Windows:  set AVALAI_API_KEY=your_api_key_here
```

هر سه عامل از یک مدل پایه استفاده می‌کنند. نویسنده و داستان‌گو یک Model Client با دمای ۰٫۸ (خلاقیت) و ویراستار
یک Model Client با دمای ۰٫۲ (قضاوت پایدار) دارند. هر دو client به یک سرویس و یک مدل وصل‌اند.

تنظیمات اختیاری:

| آرگومان / متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `--max-revisions` / `AGENT_MAX_REVISIONS` | `2` | حداکثر دور بازنویسی نویسنده (۰ تا ۲؛ بیشتر از ۲ پذیرفته نمی‌شود) |
| `--concurrency` / `AGENT_CONCURRENCY` | `2` | تعداد داستان‌هایی که هم‌زمان ساخته می‌شوند |
| `--model` | از متغیرهای بالا | نام مدل |
| `--log-dir` | `logs/` | محل لاگ همکاری عامل‌ها (`none` = خاموش) |
| `--debug` | — | لاگ مفصل + لاگ رویدادهای خود AutoGen در `autogen_events.log` |
| `AGENT_CREATIVE_TEMPERATURE` / `AGENT_EDITOR_TEMPERATURE` | `0.8` / `0.2` | دمای نمونه‌برداری |

مقدار نامعتبر در یک متغیر محیطی (مثلاً `AGENT_CONCURRENCY=two`) با یک هشدار نادیده گرفته می‌شود.

## ورودی و خروجی

ورودی یک شیء JSON مطابق قرارداد تمرین است (یا فهرستی از چنین اشیایی):

```json
{
  "story_id": "public_01",
  "child": {"first_name": "آراد", "age": 7, "interests": ["فضا", "دایناسورها"],
            "favorite_character": "ربات مهربان", "reading_level": "ابتدایی"},
  "story_request": {"theme": "دوستی و همکاری", "moral": "کمک خواستن نشانه ضعف نیست",
                    "setting": "یک ایستگاه فضایی", "target_word_count": 450,
                    "must_include": ["پایان امیدوارکننده", "یک دایناسور کوچک"],
                    "avoid": ["مرگ", "ترس شدید", "خشونت"]}
}
```

خروجی دقیقاً همین کلیدها را به همین ترتیب دارد. اگر ورودی شیء باشد خروجی شیء است، و اگر فهرست باشد خروجی هم فهرست است:

```json
{"story_id": "public_01", "title": "…", "story": "…", "moral": "…", "age_range": "6-8"}
```

- `target_word_count` می‌تواند عدد (`450`، یعنی حدود ۴۰۰ تا ۵۰۰)، بازه (`"400-500"`، `"۴۰۰ تا ۵۰۰"`، `[400, 500]`) یا
  حذف‌شده باشد (در این حالت بر اساس سن تعیین می‌شود).
- هر فیلد اضافه‌ای در `story_request` (مثلاً `"tone": "لحن آرامش‌بخش"`) به دستورالعمل عامل‌ها منتقل می‌شود.
- `age_range` از سن محاسبه می‌شود (سن ± ۱؛ مثلاً ۷ ← `6-8`).
- فایل خروجی از همان ابتدا با مقادیر خالی ساخته می‌شود و پس از کامل شدن هر داستان به‌روز می‌شود. بنابراین حتی در صورت
  خطای شبکه هم خروجی همیشه JSON معتبر است.

## حریم خصوصی و ایمنی

- فیلدهای هویتی کودک (نام خانوادگی، نشانی، تلفن، مدرسه، ایمیل، عکس، تاریخ تولد و …) پیش از رسیدن به مدل یا لاگ
  **حذف** می‌شوند. فقط نام آن فیلدها، بدون مقدار، در لاگ ثبت می‌شود. فقط نام کوچک کودک استفاده می‌شود.
- اگر درخواست، عنصر نامناسبی داشته باشد (مثلاً «نبرد خونین و کشتن اژدها»)، در دستورالعمل نویسنده با برچسب
  `SAFETY NOTE` مشخص می‌شود تا نسخه‌ی ایمنِ آن نوشته شود. ویراستار هم ایمنی را بررسی می‌کند. نمونه:
  `examples/extra_inputs.json`.
- کلمه‌های فهرست `avoid` با کد در متن جست‌وجو می‌شوند و در صورت وجود، اصلاح الزامی است.

## ساختار پروژه

```
main.py                     نقطه‌ی ورود: خواندن ورودی، اجرای عامل‌ها، نوشتن خروجی و لاگ
story_system/
  agents/author.py          عامل نویسنده   (AssistantAgent + خروجی ساختاریافته StoryDraft)
  agents/editor.py          عامل ویراستار  (AssistantAgent + خروجی ساختاریافته EditorReview)
  agents/storyteller.py     عامل داستان‌گو (AssistantAgent + خروجی ساختاریافته Narration)
  workflow.py               هماهنگ‌کننده‌ی صریح: ترتیب عامل‌ها، چرخه‌ی اصلاح، شرط توقف
  messages.py               پیام‌های هماهنگ‌کننده به عامل‌ها
  schemas.py                ساختار پاسخ هر عامل (Pydantic)
  request.py                خواندن و اعتبارسنجی ورودی، حذف داده‌ی خصوصی، ساخت دستورالعمل
  checks.py                 بررسی‌های قطعی: شمارش کلمه، طول، کلمه‌های ممنوع
  polish.py                 نگارش فارسی قطعی متن نهایی («»، ی/ک فارسی، پاراگراف‌ها)
  transcript.py             لاگ همکاری (JSONL + Markdown)
  config.py                 تنظیمات و Model Client
prompts/                    دستورالعمل سیستمی هر سه عامل (author.md، editor.md، storyteller.md)
examples/                   ۱۰ ورودی عمومی + ۳ ورودی خاص (ایمنی، حریم خصوصی، ورودی حداقلی) و خروجی‌های تولیدشده
logs/samples/               لاگ کامل همکاری عامل‌ها برای همه‌ی نمونه‌ها
evaluation/judge.py         ابزار ارزیابی مستقل با معیارهای ۱۰۰ امتیازی تمرین (ابزار توسعه، جزو گردش کار نیست)
evaluation/results/         نتایج ارزیابی
tests/                      ۶۷ تست (بدون نیاز به کلید یا شبکه)
report.md                   گزارش: معماری، نمودار، چرخه‌ی اصلاح، ارزیابی، تحلیل شکست
```

## لاگ همکاری عامل‌ها

هر اجرا یک پوشه‌ی `logs/run-<زمان>-<pid>/` می‌سازد و برای هر داستان دو فایل در آن می‌نویسد:

- `<story_id>.jsonl`: همه‌ی رویدادها به‌ترتیب، شامل پیام ورودی هر عامل (و فرستنده‌اش)، پاسخ ساختاریافته، توکن‌ها، زمان،
  نتیجه‌ی بررسی‌های قطعی و تصمیم هماهنگ‌کننده.
- `<story_id>.md`: همان مسیر به‌شکل خوانا. پیش‌نویس، بازخورد ویراستار با امتیازها و ایرادها، بازنویسی، نسخه‌ی
  داستان‌گو، بازبینی نهایی و خروجی.

نمونه: [`logs/samples/public/public_09.md`](logs/samples/public/public_09.md). بازخورد ویراستار ← بازنویسی که
طول و شخصی‌سازی را بهتر کرد ← رسیدن به سقف اصلاح به‌خاطر یک ایراد رفع‌نشده ← انتخاب بهترین نسخه ← داستان‌گو.

## تست‌ها

```bash
python -m unittest discover -s tests -v
```

تست‌ها با `ReplayChatCompletionClient` خود AutoGen (مدل ازپیش‌برنامه‌ریزی‌شده) اجرا می‌شوند و به کلید یا شبکه نیاز ندارند.
این موارد را پوشش می‌دهند: سیاست هماهنگ‌کننده (تأیید، بازنویسی، سقف دو دور، انتخاب بهترین نسخه، رد و تکرار نسخه‌ی
داستان‌گو)، انتقال واقعی پیام‌ها بین عامل‌ها، ورودی/خروجی، حریم خصوصی، ایمنی و لاگ.

## ارزیابی مستقل (اختیاری)

```bash
python evaluation/judge.py --inputs examples/public_inputs.json --outputs output.json
```

یک مدل قوی‌تر و متفاوت (`gpt-4.1`) هر داستان را با جدول امتیاز تمرین (۱۰۰ امتیاز) نمره می‌دهد. نتیجه روی ۱۰ ورودی
عمومی: **۹۲٫۰ از ۱۰۰**، در برابر ۸۷٫۴ برای پیش‌نویس نویسنده به‌تنهایی. جزئیات در `report.md`.
